## 2.3 相关量化技术

在 8-bit 混合精度训练中，量化误差的控制是保证模型精度的核心挑战。由于 FP8（E4M3/E5M2）格式本身的动态范围有限，研究界提出了多种**细粒度量化（Fine-Grained Quantization）**策略：通过为数据的不同子集分别分配独立的缩放因子，实时调整各局部区间的数值映射范围，从而最大限度地压缩量化误差。主流方案主要体现在以下几个维度。

**Per-Token 量化（激活值）。** DiT 类及 LLM 模型中的激活值（Activation）在不同 Token 维度上通常具有显著的幅值差异，并伴随频繁的离群值（Outlier）。若对整个激活张量仅使用单一的全局缩放因子（Per-Tensor），少数离群值将迫使 Scale 放大，导致其余大多数正常值被压缩至低位宽区间的密集区，产生严重的量化误差。Per-Token 策略为每个输入 Token（或 Tile）分配独立的缩放因子，使各 Token 的数值范围均能被 FP8 格式有效覆盖，从而显著降低激活值的量化损失 [Micikevicius et al., 2022]。然而，Per-Token 缩放会引入不可忽视的额外计算开销：每次量化前需对激活张量沿 Token 维度执行全局规约（Reduction）以求取各 Token 的最大绝对值 $A_\mathrm{max}$，该操作与后续矩阵乘法（MatMul）形成串行依赖，无法被并行计算掩盖，在序列较长或批量较大时会造成明显的延迟瓶颈，部分抵消细粒度量化带来的精度收益。

**Per-Channel / Per-Block 量化（权重）。** 模型权重（Weight）在不同输出通道（Channel）之间通常呈现明显不同的统计分布，部分通道可能存在显著偏大或偏小的幅值。Per-Channel 量化为每个输出通道分配独立 Scale，精确捕捉各通道的局部分布特性，有效减少通道间的量化误差。Per-Block 量化则进一步细化：以固定尺寸的矩形块（如 128×128）为单位应用独立缩放，在精度与元数据开销之间取得平衡。典型实现中，Block 大小通常设为 128×128，既能捕捉权重矩阵内部的局部分布差异，又将 Scale 元数据的数量控制在可接受范围内。

**MXFP8 微缩放格式。** Rouhani 等人 [2023] 联合微软、NVIDIA、AMD 等机构提出了 MXFP8（Microscaling FP8）格式，将缩放粒度进一步细化至每 32 个元素共享一个 8-bit 的 microscale 缩放因子。相比 Per-Channel/Per-Block，MXFP8 的细粒度缩放能够更精确地捕捉局部数值波动，在极端数据分布（如存在大量离群值）的场景下表现出更强的量化鲁棒性。MXFP8 已被纳入 OCP（Open Compute Project）规范，获得了主流硬件厂商的支持。然而，其代价是更密集的 scale 元数据存储、更频繁的内存访存以及更复杂的硬件实现要求。

**系统开销与精度的权衡。** 上述细粒度量化策略在提升精度的同时，不可避免地引入了大量额外的 Scale 元数据管理负担：Per-Token/Channel/Block 方案要求在每个训练或推理迭代步中加载、广播并存储大量 Scale 值，不仅占用宝贵的内存带宽，还增加了控制逻辑的复杂度，部分抵消了 8-bit 浮点计算本身带来的吞吐收益。从系统工程角度看，量化粒度越细，Scale 元数据的访存碎片化程度越高，硬件实现代价越大。这一系统性代价正是 HiF8 得益于其大动态范围（覆盖 38 个指数值），能够以粗粒度 Per-Tensor 量化完成训练时所规避的核心瓶颈。在 OSP-Next 模型实验中，HiF8 配合 Per-Tensor 量化与 Current Scaling，在保持与 BF16 基线相近训练精度的同时，显著简化了量化方案的系统实现，体现出良好的工程价值。
