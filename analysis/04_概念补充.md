1. Register Tokens vs LoRA：像但本质不同
相似点： 都是"少量新参数 + 冻结预训练主干"的思路。

但机制完全不一样：

LoRA	Register Tokens
加在哪	注入到权重矩阵内部（W = W₀ + AB）	拼接到输入序列外部（seq = [reg, x]）
改变了什么	改变了线性层的变换能力	增加了序列中的"全局节点"
推理时	A、B 可以合并进 W₀，零额外计算	register tokens 必须一直存在，有计算开销
参数量	取决于 rank，通常 0.1%~1%	N × dim，固定
作用	改变模型的"变换方式"	充当稀疏注意力下的信息中转站
register tokens 更像 prompt tuning（NLP 里的 soft prompt）——往输入里加一些可学习的"虚拟 token"，让模型通过 attention 机制自己学会如何利用它们，而不直接修改权重。

在 OSP-Next 里它的特殊性在于：skiparse 的稀疏注意力导致很多 token 之间互相看不到，register tokens 在 mask 里强制全局可见，相当于给每个 token 都保留了一条"紧急通道"可以获取全局信息。

2. Flow Matching 是什么
一句话： 它是扩散模型的训练目标和推理框架，定义了"怎么加噪、怎么去噪、怎么算loss"。

直觉理解
经典扩散模型（DDPM）是这样的：


干净数据 x₀  →  逐步加高斯噪声  →  纯噪声 xₜ
训练：让模型学会预测噪声 ε
Flow Matching 换了一个视角：


把"加噪过程"看作一条从 x₀ 流向 xₜ 的轨迹（flow）
训练：让模型直接学会预测这条轨迹的"速度方向"（vector field）
数学上，在时间步 t ∈ [0,1]，插值公式是：


xₜ = (1 - t) · x₀  +  t · noise
目标速度（ground truth）是：


v* = noise - x₀
模型学的就是：给定 xₜ 和 t，预测 v_θ(xₜ, t)，让它接近 v*。

Loss 就是：


loss = mse(model_output, v*)  # train_osp.py L537
loss = scheduler.training_losses(model_output, latents, prior_dist)
它比 DDPM 好在哪里
DDPM	Flow Matching
轨迹	弯曲、随机游走	接近直线（更短路径）
推理步数	需要几十到几百步	可以几步甚至1步
训练稳定性	较稳定	更稳定（梯度更干净）
理论框架	基于 SDE/Markov chain	基于 ODE，更简洁
Wan2.1 和 OSP-Next 用的是带 dynamic shifting 的 flow matching（config里 use_dynamic_shifting: True）——根据视频分辨率动态调整时间步的分布，让模型在高分辨率时把更多训练时间花在难的时间步上。

在这个项目里的位置

train_osp.py
  └── scheduler = schedulers["flow_matching"](...)   # 初始化
        ├── q_sample()     # 推理时：给定 x₀ 和 t，生成 xₜ（加噪）
        └── training_losses()  # 训练时：计算 MSE(model_output, v*)
模型（OSPNextModel）本身不知道 flow matching 的存在，它只是一个 (xₜ, t, text) → v_θ 的函数，flow matching 是套在外面的训练框架。
