这是一份关于HiF8的介绍，

摘要
随着大模型训练对算力效率、访存带宽与数值稳定性的要求不断提升，低比特浮点格式正在成为混合精度训练的重要演进方向。
第一章 HiF8 数据格式介绍
本章首先介绍华为全新自研的 8-bit 浮点数据格式 HiF8（HiFloat8），重点说明其编码模式及对特殊值的支持特性。相较于传统的 FP8（E4M3/E5M2）格式，HiF8 通过优化阶码与尾数的分配方式，显著提升了动态范围与表示精度。在此基础上，HiF8 提出了一种创新的通用浮点编解码方法，使其字段宽度、动态范围及精度均可根据具体场景的需求进行缩放。值得注意的是，HiF8 额外引入了 Dot 字段。如表 1 所示，该格式由符号（Sign）、点位（Dot）、阶码（Exponent）和尾数（Mantissa）四个核心字段组成。

字段	宽度（bit）	说明
符号（S）	1	数值符号，1 表示负，0 表示正
点位（D）	2~4	指示指数域宽度及 Denormal 编码模式（DML）
阶码（E）	D 位	采用符号-幅度编码（Sign-Magnitude）
尾数（M）	1~3	省略前导 1 的尾数位

符号域 (Sign Field)：1 位，用于决定 HiF8 数值的正负符号。默认情况下，1 表示负号，0 表示正号。
点位域 (Dot Field)：采用前缀编码，不同编码长度对应不同的 Dot 值，如表 2 所示。

阶码域 (Exponent Field)：D 位（包含一个未存储的、值为 1 的隐含前导数值位），其中 D 等于 Dot 字段的编码值，且 D∈{0, 1, 2, 3, 4}。

尾数域 (Mantissa Field)：1 到 3 位，使用无符号整数编码。对于 HiF8 的规格化数，尾数表示有效数字中的小数部分，即二进制小数点右侧的部分。
 

1.1 Normal 编码模式
图 1：HiF8 的 Normal 编码模式结构及其阶码幅值分配示意图

图 1 展示了 HiF8 的 Normal（规格化）编码模式。为确保不同位宽阶码域对应的指数范围互不重叠，并实现无冗余编码，HiF8 采用 Sign-Magnitude 编码方案，并将幅值的最高位设为隐含位，不占用实际存储空间。

具体而言：

当 Dot = 0 时，阶码不占据位宽，且 E 直接等于 0；
当 Dot = 1~4 时，固定阶码幅值的最高位为 1（图 1 中的红色数字）。
在此规则下：

当 Dot = 1 时，阶码 E 只能表示 ±1，不包含已经编码的 0；
当 Dot = 2 时，阶码 E 只能表示 ±[2, 3]，不包含已经编码的 [-1, 1]。以此类推，Dot 域指示的 0~4 共五种位宽阶码，共编码了 [-15,  15] 的指数，且彼此之间不重复，实现了无冗余编码。
 
此外，HiF8 采用大位宽的 Dot 域匹配小位宽（小幅值）阶码域的设计，从而实现了尾数精度的平滑渐变而非断层式跳变。观察可见，在 E = [-3,  3] 时，有 3-bit 尾数。然后随着阶码幅值变大，Normal 模式下的尾数位宽才逐渐收缩至 1-bit。这种精度渐变特性，也是 HiF8 优于其借鉴对象 Posit 数据格式的重要原因之一。

为了支持更大的动态范围，HiF8 还采用了不同于 IEEE 754 风格的 Subnormal / Denormal 方案。如图 2 所示，在 Denormal（非规格化）模式下：

编码逻辑转换：当 Dot 域指示当前数值处于 Denormal 模式时，HiF8 将不再保留独立的阶码域。此时，原有的 3-bit 尾数空间（可编码 0~7 共 8 个离散值）将被直接复用，以映射并扩展极小值的指数表示范围。
指数范围扩展：在 Normal 模式支持的 [-15,  15] (共 31 个指数)的基础上，Denormal 模式额外开辟了 [-22,  -16] 共 7 个指数。其中，编码 0 对应  -23，用于表示特殊值 Zero 和 NaN。
性能对标：由此，HiF8 实现了覆盖 [-22,  15] 共 38 个指数的大动态范围，已经非常接近 FP16 的 [-24,  15] 的指数覆盖范围。同时，由于 [-15,  -8] 区间本身是 1-bit 尾数，新增扩展的 [-22,  -16] 区间对应 0-bit 尾数，二者在表示精度上保持连续过渡，而非突变。

1.4 HiF8 的核心特性
 HiF8 具备一系列专为大模型（LLM）训练量身定制的优良特性，核心优势主要体现在以下三个方面：

契合数据分布的锥形精度（Tapered Precision）：传统的 FP8（E4M3/E5M2）因阶码位宽固定，往往难以同时兼顾深度学习所需的动态范围与有效精度。考虑到神经网络的参数与激活值通常呈现类高斯分布，HiF8 创新性地采用了锥形精度分布（如图 3 所示），将更高的精度集中在高频出现的数值区间，从而更好地匹配模型数据特征。

图 3：8-bit 浮点数格式有效位-指数示意图

无冗余编码：HiF8 的阶码采用原码编码，并将固定的 1-bit 高位设为隐含位，不占用实际存储空间，从而确保不同位宽阶码的表达范围互不重叠，最终实现无冗余编码。
大动态范围：通过特殊的 Denormal 设计，将综合指数范围从 [-15,  15] 扩展至 [-22,  15]，共覆盖 38 个指数值，已经接近 FP16 的 40 个综合指数值表达范围。表 4 对 HiF8、FP8 与 FP16 的典型值及关键特征进行了总结和对比。可以看到，HiF8 在 8-bit 位宽限制下，通过匹配数据分布的锥形精度特性，在保证神经网络训练与推理所需精度的前提下，显著扩大了格式的动态范围，为神经网络提供了能力更全面的 8-bit 单格式表示。

第二章 量化方案
在执行量化时，高精度数据（如 FP32/BF16）向低比特（如 FP8）转换的核心在于缩放处理（Scaling）。针对给定数据块 X，需通过乘以一个缩放因子（Scaling Factor, Scale），使 X 中的原始数值能够安全、无溢出地映射至低比特的动态范围内。公式（1）和公式（2）描述了量化过程中的基本缩放原理。其中，F8max 表示目标 8 比特浮点格式可表示的最大值（例如 FP8-E4M3 的最大值为 448），Amax 表示数据块 X 中元素的最大绝对值。公式（1）用于计算缩放因子 Scale，公式（2）用于将高精度数据映射至低比特表示范围。

尽管 8-bit 浮点数（FP8）在动态范围上相较于定点数具有天然优势，但在仅有的 8 位位宽限制下，其精度表达能力与数值覆盖范围仍然有限。为了最大限度地抑制从高精度（如 FP16 / BF16）向 FP8 转换时的量化损失，业界通常引入“细粒度量化（Fine-Grained Quantization）”策略。 如图 4 所示，该策略通过大幅增加缩放因子（Scaling Factor）的密度来实时调整数据映射范围，主要体现在以下两个维度：

激活值的 Per-Token 细粒度（针对动态分布）：由于 LLM 中的激活值（Activation）通常在不同的 Token 维度上具有较大的动态范围差异，并伴随频繁的离群值。Per-Token 缩放会为每个输入 Token（或 Tile）应用一个独立的缩放因子，以确保每个 Token 的核心数据范围能被 FP8 格式有效覆盖，从而保持量化精度。
权重的 Per-Channel / Per-Block 细粒度（针对静态分布）：模型权重（Weight）的分布在不同的输出通道（Channel）或权重块（Block）之间通常具有不同的分布特征。Per-Channel / Per-Block 缩放通过为每个通道或每个权重块应用独立的缩放因子，来进一步降低量化误差，提升模型推理精度。典型的 Block 大小可设为 128 × 128。
然而，这种对精度的极致追求，引入大量的 Per-Token / Channel / Block 缩放因子，会显著增加硬件实现和控制逻辑的复杂性。在推理过程中，系统需要频繁加载、存储并应用这些额外的缩放因子，从而带来额外的内存带宽开销和计算延迟，部分抵消 8-bit 浮点计算本身带来的加速收益。



图 4：常见量化粒度示意图

由于 HiF8 具备更大的动态范围，在训练中往往可以采用粗颗粒度的 Per-Tensor 量化，而 FP8、MXFP8 等格式往往需要 Per-Block 量化。

第三章 训练方案
3.1 常见训练方案
在介绍基于低比特格式（如 HiF8）的量化训练方案之前，有必要先回顾目前业界最广泛使用的基线方案——基于 BF16 的混合精度训练。

BFloat16（BF16）格式
BF16 是 2017 年提出的一种专为 Deep Learning 设计的 16-bit 浮点数格式。在内存布局上，它由 1-bit 的 Sign、8-bit 的 Exponent 和 7-bit 的 Mantissa 组成。 与传统的 FP16（5-bit Exponent，10-bit Mantissa）相比，BF16 牺牲了 Mantissa 的精度，但保留了与高精度数据类型 FP32 完全相同的 Exponent 位宽。这意味着 BF16 拥有与 FP32 相同的动态范围（约 10-38  到  1038）。在神经网络的训练中，模型参数和梯度的分布通常跨越极大的数值范围，使用 BF16 可以有效避免由于表达范围不足而导致的上溢或下溢，同时其较小的位宽又能显著降低显存占用与内存带宽开销。
基于 BF16 的混合精度训练
主流深度学习框架在支持 BF16 训练时通常采用自动混合精度（Automatic Mixed Precision, AMP）机制。 该范式在图层或算子层级选择合适的数据类型：在前向计算（Forward Pass）和反向传播（Backward Pass）中，框架会将计算密集型算子（如 MatMul、Convolution）的输入自动下采样转换为 BF16，以充分发挥底层硬件的加速优势；而对于对数值精度高度敏感的算子（如 Softmax、LayerNorm、Loss 计算等），则保持 FP32 以确保数值稳定性。此外，在 Optimizer 的参数更新步骤中，系统往往在内存中维护一份 FP32 高精度主权重（Master Weights），从而避免因 BF16 Mantissa 精度不足而导致的权重更新停滞。
在上述混合精度方案基础上，基于缩放（Scaling）技术的 8-bit 混合精度训练可以进一步提升训练效率。

3.2 缩放方案
当前主流的 8-bit 混合精度训练方案通常涉及两类缩放策略：Current Scaling 和 Delayed Scaling。如图 5 所示，Current Scaling 在每个训练步都遍历输入 X  中的高精度数据，获得最大绝对值 Amax，并基于该 Amax 值完成缩放。这意味着求取 Amax 与计算 Scale 的过程在每次迭代中都需要执行，且与下游计算（如 MatMul）串行，从而部分抵消 8-bit 带来的性能收益。相较之下，图 6 展示的 Delayed Scaling 利用历史统计值对当前训练步的 Amax 作估计，将遍历输入 X  求取 Amax 的操作与后续运算解耦，因此能够更充分地发挥 8-bit 训练的性能优势。

图 5：Current Scaling 以 iteration 为周期计算 Amax，将输入 X 缩放至 Float8 表达范围内

图 6：Delayed Scaling 以 interval = K iterations 为周期计算 Amax，将输入 X 缩放至 Float8 表达范围内，其中 N_guard 为防止上溢的保护参数

常用于 8-bit 混合精度训练的 FP8-E4M3 因其动态范围较小，往往需要采用细颗粒度的 Current Scaling，而 HiF8 得益于其在精度和动态范围间所取得的平衡，能够采用 Delayed Scaling，并以较长的周期（interval）估计 Amax 值，同时仍保持训练稳定性。

总结
本文围绕 HiF8 的数据格式设计、量化方案、训练框架支持以及实验结果进行了分析

从当前结果看，HiF8 在数值范围、训练稳定性和系统开销之间取得了较好的平衡。对于希望降低访存压力、提升训练吞吐并控制实现复杂度的大模型训练场景，HiF8 是一种具有工程应用价值的 8-bit 混合精度训练方案。
